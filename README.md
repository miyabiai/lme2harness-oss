# lme2harness

**L Message（エルメ）の顧客データを、L Harness（[line-harness-oss](https://github.com/Shudesu/line-harness-oss)）へまるごと移すツール**です。

L Harness は無料でも、エルメで作り込んだ友だち・タグ・会話・ステップ配信を手で移すのは大変です。lme2harness なら、**L Harness のセットアップが終わっていれば、コマンド 3 つ**で移せます。

```bash
mkdir lme-migration && cd lme-migration
npx lme2harness init       # L Harness の設定を自動で読み込み、API キーを貼る
npx lme2harness login      # ブラウザでエルメにログイン
npx lme2harness migrate    # 点検 → 取り出し → 変換 → 投入 → 照合 まで一気に
```

**コマンドを打たずに移したいとき**は、Claude Code か Codex のチャット欄にメッセージを1回貼って送るだけ。あとは AI とやり取りするだけで終わります → [コピペで移行](docs/コピペで移行.md)

- エルメ公式の口（公式 MCP・公開 API）だけを使います。画面の自動操作はしません
- 何度実行しても同じ結果になります。途中で止まっても、同じコマンドで続きから再開できます
- 移せないものは「移せない」とレポート（`out/report.md`）に書きます。黙って落としません
- 移したステップ配信・自動応答・フォームは **停止状態** で入るので、エルメと二重に送られることはありません
- 切り替えまでエルメと並行で動かすための **ブリッジ** も入っています

## 必要なもの

| もの | 備考 |
|---|---|
| Node.js 22 以上 | `node -v` で確認。Windows でも動きますが、つまずいたら WSL（Windows 上の Linux）で動かしてください |
| セットアップ済みの L Harness | `npx create-line-harness` を最後まで終えていること |
| L Harness の API キー | セットアップ完了画面に一度だけ出る「API Key」 |
| エルメのアカウント | `login` でブラウザからログインします |

`init` は L Harness の導入フォルダ（既定の `~/.line-harness`）を自動で探し、Worker の URL・データベース（D1）の名前などを設定ファイルに書き込みます。create-line-harness が導入フォルダの `.line-harness-config.json` に API キーを残していれば読み込みますが、版によっては完了時に消されるので、その場合は完了画面の API Key を貼ります。別の場所に入れた場合は `npx lme2harness init --harness-dir <フォルダ>` で指定してください。

## 移せるもの

| エルメ | L Harness での行き先 | 判定 | 補足 |
|---|---|---|---|
| 友だち（LINE ID・表示名・追加日・ブロック状態） | 友だち | ○ | アイコン・最新の表示名は LINE から取り直します |
| 友だち情報（標準・カスタム項目） | 友だちのメタデータ | ○ | 項目名をキーにして保存 |
| タグ・タグ付け | タグ | ○ | 同じ名前の既存タグは使い回します |
| 対応ステータス | タグ「対応:◯◯」 | △ | L Harness に同じ機能が無いためタグで再現 |
| 会話履歴（文字・画像・スタンプ等） | チャット画面 | ○ | ログインあり＝全期間、API キーだけ＝直近100件 |
| ステップ配信（タイミング・本文・付与タグ） | シナリオ | ○ | 停止状態で作成。開始のきっかけは手動 |
| ステップ配信の進み具合 | シナリオの進行状態 | ○/△ | 配信中の人は会話履歴から「何通目まで届いたか」を復元して続きから。履歴が残っていない古い人だけ一時停止 |
| テンプレート（文字・画像・Flex） | テンプレート | ○ | 複数メッセージは「名前 (1/n)」に分割 |
| あいさつメッセージ | 友だち追加シナリオ | ○ | 停止状態で作成 |
| 自動応答（キーワード） | 自動返信 | ○ | 停止状態で作成。時間帯の条件は対象外 |
| フォーム・回答 | フォーム・回答 | ○ | 説明文・ファイル添付の項目は対象外 |
| 流入経路 | 流入経路 | △ | 名前・コード・付与タグのみ |
| リッチメニュー | リッチメニュー | ○ | LINE 上のメニューを L Harness の管理画面に取り込み（表示は変わりません）。タブ切替入りは対象外 |
| サロン・面談予約 | 予約（メニュー・担当者・予約） | △ | 出勤時間と予約フォームの質問は対象外 |
| レッスン予約 | イベント予約（コース＝イベント） | △ | 予約が入っている枠と予約を移します。予約の無い枠と定員はエルメが出さないので管理画面で追加。イベントは非公開で作成 |
| イベント予約 | ― | × | エルメに参加者を取り出す口が無いため |
| 商品・決済・購入履歴 | ― | × | 購入履歴はメタデータに保持 |
| 一斉配信の履歴・クリック計測 | ― | × | |

画像・ファイルはエルメ側の URL を参照しています。**エルメを解約すると開けなくなる**ので、必要なものは L Harness の管理画面で登録し直してください。

## 使い方

### 1. 準備（init → login → doctor）

```bash
npx lme2harness init       # 設定ファイルと .env を作り、API キーを聞かれたら貼る
npx lme2harness keys       # （聞かれなかったとき）.env をテキストエディットで開くので、API キーを貼って保存
npx lme2harness login      # ブラウザが開くのでエルメにログイン → 移行元のアカウントが自動で設定される
npx lme2harness doctor     # 準備ができているか点検（何も書き換えません）
```

`login` は保存済みのログインが使えるときはブラウザを開きません（移行元を選び直すときは `login --bot-id <bot_id>`、ログインし直すときは `login --relogin`）。移行を別のパソコン（サーバーや遠隔の Mac）で動かしていて、ブラウザは手元のパソコンで開きたいときは `npx lme2harness login --no-browser --timeout 3600` で URL だけ表示させ、手元のパソコンで `ssh -N -L 8976:127.0.0.1:8976 <移行を動かしているマシン>` を実行してから、その URL を手元のブラウザで開いてください（承認後の戻り先が 127.0.0.1:8976 なので、転送が要ります）。

`doctor` が ✗ を出したら、すぐ下の「→」の案内どおりに直してください。よくあるのは次の 2 つです。

- **L Harness の API キーが違う** → `.env` の `HARNESS_API_KEY` を貼り直す
- **データベースに書き込めない** → `npx wrangler login` で L Harness と同じ Cloudflare アカウントにログイン

### 2. 移行（migrate）

```bash
npx lme2harness migrate
```

次の順に進みます。書き込む前に一度確認を求めます。

1. 点検
2. エルメから取り出し（`./snapshot`。友だち1万人で30分前後）
3. L Harness の形に変換（`./out/report.md` に「何が移るか・移らないか」）
4. L Harness に書き込み
5. 件数の照合
6. リッチメニューの取り込み
7. アイコン・表示名を LINE から取得

各段を個別に動かすこともできます（`extract` / `plan` / `apply` / `verify` / `richmenu` / `enrich`）。

### 3. 並行運用（bridge）

LINE の Webhook URL は 1 つしか設定できません。切り替えまでの間は、エルメの **「Webhook転送」** で L Harness にも同じ出来事を流します。

```bash
npx lme2harness bridge --deploy
```

表示された 2 つの URL を、エルメ管理画面の「Webhook転送」に設定して有効にしてください（反映まで約1分）。「L Messageデータ転送」の **署名シークレット** を `.env` の `LME_WEBHOOK_SECRET` に貼り、もう一度 `bridge --deploy` を実行します。

- **2 つの URL は人に見せないでください。** エルメの「LINE公式アカウントデータ転送」には署名が付かないため、URL の末尾のトークンだけが鍵です。漏れたら `npx lme2harness bridge --deploy --rotate-token` で、同じ Worker のまま 2 つのトークンを作り直します（配備が終わると前の URL は使えなくなるので、新しい URL をエルメに貼り直してください）。
- ブリッジは L Harness へ渡し終えてから返事をします。渡せなかったときは 502 を返し、エルメが送り直せるようにします（エルメの 10 秒の制限に収めるため、8 秒で終わらない分は返事の後に続けます）。
- Worker の名前は、フォルダごとに `lme2harness-bridge-<8桁>` になります（同じ Cloudflare アカウントで別のフォルダのブリッジを上書きしないため）。前の版で作ったブリッジは名前も URL もそのままです。別の移行先（D1・L Harness）向けに作ったフォルダで配備し直そうとすると止めます。
- `bridge` を実行し直すと、`./bridge` の Worker をこのツールの版に合わせて新しくします（前のものは `.lme2harness/bridge-backup/` に控えます）。配備中の Worker に届けるには `--deploy` を付けてください。`bridge/wrangler.toml` に足した重複排除（`[[kv_namespaces]]` の `DEDUP`）の設定は残ります（コメントにした設定は引き継ぎません）
- 前の版で作ったブリッジを、別の移行先（L Harness・D1）向けに配備し直そうとしたときは止めます。`--rotate-token` のトークンは、配備し終えてから保存します（途中で失敗したら前の URL のまま使えます）
- エルメのタグ一覧を一時的に引けなかったときは 502 を返して送り直してもらいます。エルメで見つからなかったタグは覚えず、次の出来事で引き直します
- ブリッジは `X-Lme-Timestamp`（エルメの送信時刻）が今から 5 分以上ずれた通信を断ります（盗み見た通信の使い回し対策。`MAX_CLOCK_SKEW_SECONDS` で変更可）。
- 署名シークレットを再生成したときは、新しい値を `LME_WEBHOOK_SECRET`、前の値を `LME_WEBHOOK_SECRET_PREVIOUS` に貼って `bridge --deploy` します。前の値は登録から 2 分だけ受け付け、その後は断ります。済んだら `.env` の `LME_WEBHOOK_SECRET_PREVIOUS` は消してください。

```
LINE → エルメ ──(LINE公式アカウントデータ転送)──→ ブリッジ ──→ L Harness（メッセージ・友だち追加）
           └──(L Messageデータ転送)──────────→ ブリッジ ──→ L Harness（タグの付け外し・友だち情報）
```

並行運用中に **L Harness でやってはいけないこと**:

- シナリオ・自動返信を有効にする（エルメと二重に送られます）
- 取り込んだリッチメニューで「公開」「公開停止」を押す（LINE 上のメニューが作り直され、エルメが人ごとに出しているメニューが外れます）
- 移したレッスン（イベント）を公開する（エルメと L Harness の両方で予約を受け付けてしまいます）

予約のリマインドは、エルメと二重に届かないよう移行時には作りません。

### 4. 切り替え

ステップ配信の予定が入っていない時間帯に、1〜5 を続けて行ってください（間にエルメが送った分は、L Harness からもう一度送られることがあります）。

1. もう一度 `npx lme2harness extract` → `plan` → `apply`（増えた分だけ足されます。ステップ配信の進み具合も最新になります）
2. エルメでステップ配信・自動応答を止める
3. LINE Developers コンソールで Webhook URL を L Harness の `/webhook` に変え、エルメの Webhook 転送を無効にする
4. L Harness でシナリオ・自動返信を有効にする
5. エルメで設定していた「誰にどのリッチメニューを出すか」を L Harness の自動化で作り直す（`richmenu` コマンドが一覧を出します）
6. レッスン予約を使っていたら、L Harness のイベントに予約の無い枠と定員を足して公開し、イベントを一度保存してリマインドを作る

### D1 の無料枠について

Cloudflare D1 の無料枠は **1 日 10 万行の書き込み**（UTC 0 時＝日本時間 9 時にリセット）です。友だち数千人の移行は会話履歴・タグ付けだけで数十万行になるので、`apply` の後に `enrich` や L Harness 自体の更新が「D1's free tier daily row write limit」で止まることがあります。翌日 9 時以降にやり直すか、Workers 有料プラン（月 5 ドル）にすると止まりません。本番で使うなら有料プランをおすすめします。

## 仕組みと安全策

- ID はエルメの ID から決まった値で作ります（UUID v5）。何度流しても重複しません
- 既に L Harness にいる友だちの表示名・アイコンは上書きせず、エルメ由来の情報とタグだけ足します。メタデータは L Harness 側で足された項目（フォームの回答・ブリッジが入れた友だち情報）を残し、エルメ側の元データ（`_lme`）だけ今回の取得結果に置き換えます。追加日は古い方を残します
- 既にあるチャットの対応状態（未読・対応済み）と L Harness で人が書いたメモは、移行し直しても変えません（最終日時は新しい方にします）
- 停止・有効の状態は、移行し直しても変えません（L Harness で有効にしたシナリオ・自動応答・フォームを止めず、無効にした流入経路・メニューを戻しません）
- L Harness で有効にした自動応答・フォームは、移行し直しても中身（返信の文・設問・送信後の動き）を変えません。無効のものはエルメの最新の内容にします。流入経路・メニューは最初から有効で入るので、有効／無効だけ残して中身はエルメの内容にします
- L Harness で有効にしたシナリオは、移行し直しても設定・ステップを変えず、ステップも足しません。新しく入る人は「一時停止」で入れ、自動では送りません。進行状態も上書きしません（`activate_automations` で最初から有効にする設定のときは、これまでどおり書き換えます）
- エルメで配信を止めた人は、シナリオに「一時停止」で入れます（前回の移行で配信中として入れた人も止まります。ただし L Harness でまだ有効にしていないシナリオに限ります。有効にした後は L Harness 側の進み具合を優先するので、止めたい人は L Harness の管理画面で止めてください）
- wrangler には自分のログフォルダへ結果を書かせず（`WRANGLER_WRITE_LOGS=false`）、wrangler が失敗したときのエラー文にも SQL の中身（顧客データ）を出しません
- wrangler・ブラウザはシェル（コマンドプロンプト）を通さずに起動します。Windows では node で wrangler の本体を直接動かします
- API キーは https（と手元で動かす `http://localhost`）の L Harness にだけ送ります
- API キーなどの秘密はログに出しません。`.env` と `.lme2harness/` は人に渡さないでください
- `snapshot/` と `out/` には顧客の名前・会話・フォーム回答が入るので、本人だけが読める権限（フォルダ 0700・ファイル 0600）で書きます。移行が終わったら消してください
- wrangler が手元に無いときは、版を固定して `npx wrangler@<版>` で起動します（最新版をその場で取ってこない）

## 困ったとき

- まず `npx lme2harness doctor` の「→」の案内を試してください
- 不具合（エラーが出る・件数が合わない）は [GitHub Issues](https://github.com/miyabiai/lme2harness-oss/issues) へ。API キー・顧客の名前は消してから貼ってください
- やり方がわからない・AI に任せていて詰まったときは、作者（みやび｜Lゼロ）の LINE で相談を受け付けています → https://line.miyabiai.jp/r/oss-readme-261024 （パソコンで開くと QR コードが出るので、スマホで読み取ってください）
  - 無料で、個人で返しているため、お返事まで時間がかかることがあります。移行の結果を保証するものではありません
  - API キー・`.env`・`snapshot/` の中身・顧客の名前が写った画面は送らないでください

## 開発

```bash
pnpm install
pnpm test     # vitest
pnpm build
```

L Harness v0.24.1 のデータベースの形（`packages/db/bootstrap.sql`）を基準にしています。本番に流す前に `plan --local-schema <bootstrap.sql>` で手元の SQLite に通して確かめられます。

## 変更履歴

### 次の版（未公開）

並行運用中に移行し直したとき、L Harness 側で変わった状態を壊さないための修正。

- `apply`: 友だちのメタデータを丸ごと上書きしていたのを、L Harness 側の項目を残して足す形にした。追加日（`created_at`・`first_followed_at`）は古い方を残す
- `apply`: 既にあるチャットの対応状態・人が書いたメモを上書きしない。最終日時を古くしない
- `apply`: あいさつ・自動応答・流入経路・メニューの有効／無効を、移行し直したときに初期値へ戻していたのを直した
- `apply`: L Harness で有効にしたシナリオの設定・ステップを書き換えず、新しく入る人は「一時停止」で入れる。エルメで配信を止めた人も「一時停止」で入れる（今までは入れず、前回「配信中」で入れた人がそのまま残っていた。L Harness でまだ有効にしていないシナリオに限る）
- `verify`: L Harness で有効にしたシナリオのステップは数えない
- `apply`: L Harness で有効にして直した自動応答・フォームの中身を、移行し直したときにエルメの内容へ戻していたのを直した
- `bridge`: L Harness へ渡せなかったときに 200 を返していた（エルメが送り直さず取りこぼす）のを 502 にした。重複排除の印は渡せた後に付ける。L Harness のエラー応答も失敗として数える
- `bridge`: `--rotate-token` を足した。新しいフォルダの Worker 名をフォルダごとに変える。`wrangler.toml` の KV の設定を残す
- `bridge`: 実行し直しても `./bridge` の Worker を新しくしていなかった（直した Worker が既存の利用者に届かない）のを、版に合わせて新しくするようにした。前の版で作ったブリッジも移行先を照らし合わせる。`--rotate-token` は配備し終えてから保存する
- `bridge`: エルメのタグ一覧が一時的に失敗したとき「無いタグ」として捨て、10 分覚えていたのを、502 で送り直してもらうようにした。見つからなかったタグは覚えない
- この版で `plan` し直すと SQL の中身が変わるので、最初の `apply` は全部を1回流し直します（何度流しても同じ結果ですが、件数が多いと時間がかかります）
- wrangler の出力を受け取りの切れ目で文字にしていて、日本語・絵文字が壊れることがあった（件数の照合は数字なので影響なし）のを直した。wrangler のログに結果を書かせない。エラー文に SQL の中身を出さない
- Windows でシェル経由に起動していて、SQL・URL の空白や `&` で引数が切れていた（`verify`・`doctor` の照合、`login` のブラウザ）のを、シェルを通さない形にした
- `harness_url` が `http://` のときに API キーを平文で送っていたのを、https と localhost だけにした

### 0.1.1（2026-10-24）

友だち数千人・会話 10 万件規模のエルメを実際に移して見つかった取りこぼしの修正と、遠隔での使い勝手。

- `extract`: MCP のページ送りで `pagination.total` が「そのページの件数」しか返すツール（`get_form_responses`・`list_conversations`）があり、2 ページ目以降を読んでいなかった。limit に満たないページまで読むように変更（数千件あるフォーム回答が 100 件で止まっていた）
- `extract`: 会話一覧（確認状態・対応ステータス・最終日時）を `conversation_index.json` にマスタと一緒に保存し、`plan` が友だちごとの不足分を補う。対応ステータスは MCP の `handling_status_id` / `handling_status_name` を読む（今まで全員「無し」になっていた）
- `plan`: ステップ配信の開始・停止・空ステップの記録（`message_type=scenario` の JSON 文字列・`stop_scenario`・`scenario_empty_step`）を会話に入れない。本文が空の送信記録も入れず、件数をレポートに出す
- `plan`: ボタン型（カード）メッセージをタイトル・本文・ボタン名の文字メッセージにする（今まで JSON のままだった）
- `login`: 保存済みのログインが使えるときはブラウザを開かない（`--relogin` で再ログイン、`--bot-id` で移行元の選び直しだけ）。`--no-browser` / `--timeout` で、別のパソコンのブラウザから承認できる（ssh のポート転送 8976）。承認後にブラウザの接続を閉じ、プロセスが残らないようにした
- `init`: 導入フォルダの `.line-harness-config.json` に API キーが残っていれば読み込む（create-line-harness の版によっては完了時に消されるので、無ければ従来どおり貼る）
- `enrich`: 最初の 1 回で全員エラーなら止めて、原因の調べ方（D1 無料枠の書き込み上限・`wrangler tail`）を出す
- `apply`: Cloudflare 側の一時的な失敗（「File could not be uploaded. Please retry.」など）は待って最大 3 回再試行する。D1 への取り込みは 1 データベース 1 本ずつしか進まない（同時に流しても失敗する）ので、1 ファイル 3〜5 秒 × ファイル数が目安（友だち数千人・会話 9 万件規模で 500 ファイル超・約 35 分）
