# コピペで移行（コマンドを打たない手順）

コマンドは打ちません。**下のメッセージを1回だけ、Claude Code か Codex のチャット欄に貼って送ってください。** あとは AI が最後まで進めて、あなたの番になったときだけ声をかけてきます。あなたはチャットで返事をするだけです。

1. 下の枠の右上にある **コピーボタン** を押す
2. Claude Code か Codex のチャット欄に貼って、送る
3. あとは AI とやり取りするだけ

## あなたの番は、この6回だけ

| 段階 | AI がやること | あなたがやること |
|---|---|---|
| ① 準備 | ツールを用意して、設定を作る（L Harness の導入フォルダから API キーも読み込む） | **API キーを読めなかったときだけ**、テキストエディットが自動で開くので貼って ⌘S で保存 |
| ② ログイン | エルメのログイン画面を開く | ブラウザでエルメにログインして「許可」を押す |
| ③ 移行 | 取り出して変換し、「何が移るか」を表にする | 表を見て「OK」と送る |
| ④ 並行運用 | 中継の仕組みを作り、エルメに貼る URL を出す | テキストエディットにシークレットを貼る・エルメの画面に URL を貼る |
| ⑤ 切り替え | 切り替えの順番を1つずつ案内する（切り替えの日に） | 案内どおりに画面を操作して「できた」と送る |
| ⑥ 後片付け | 顧客データの入ったファイルを消す | 消すものを見て「OK」と送る |

**API キーはチャットに貼りません。** 貼るのは、AI が開いたテキストエディットの中だけです。貼って ⌘S（Windows は Ctrl+S）で保存すると、AI が受け取って先に進みます。

## 始める前に用意するもの

- **L Harness のセットアップが終わっていること**（`create-line-harness` を最後まで終えた状態）
- **L Harness の API キー**（セットアップ完了画面に一度だけ出る「API Key」。メモしておく）
- **エルメにログインできること**
- **Claude Code か Codex**（パソコンで動かすもの）

## 貼るメッセージ（これ1つだけ）

```text
エルメ（L Message）から L Harness へ、顧客データを引っ越したいです。あなたが最後まで進めてください。私はコマンドを打てないので、私とはチャットでやり取りするだけにしてください。

【使うツール】
lme2harness（https://github.com/miyabiai/lme2harness-oss）を使います。npm にはまだ公開されていないので、次のように用意してください。
- ホームフォルダの lme2harness-oss に git clone して、npm install → npm run build
- 作業フォルダはホームフォルダの lme-migration。コマンドは作業フォルダの中で「node <lme2harness-oss の場所>/dist/cli.js <コマンド>」で実行する
- 細かい仕様は README.md と docs/手順書.md を読む

【進め方】終わったら次へ。途中から再開するときは、作業フォルダの状態を見て続きから進める
① 準備：init を実行（L Harness の導入フォルダから API キーも自動で読む）→ .env に HARNESS_API_KEY が入らなかったときだけ keys を実行して、私に L Harness の API キーを貼ってもらう
② ログイン：login を実行して、私にエルメへログインしてもらう → doctor で点検し、✗ があれば直す（Cloudflare へのログインが必要なら npx wrangler login を実行して、私にログインしてもらう）
③ 移行：migrate を実行する。書き込む直前で止まるので、out/report.md を「移るもの・移らないもの」のやさしい表にして見せ、私の「OK」を待ってから migrate --yes で最後まで進める
④ 並行運用：keys --for bridge で、私に LINE のチャネルシークレットを貼ってもらう → bridge --deploy → エルメの「Webhook転送」画面のどこに何を貼るか、画面の順番どおりに案内する → 署名シークレットも同じ keys で貼ってもらったら、もう一度 bridge --deploy
　ここで一度止まって「切り替えの日に、このチャットで『切り替えたい』と言ってください」と伝える
⑤ 切り替え（私が言ったら）：README の「4. 切り替え」の順番で進める。私の画面操作は1つずつ案内して、「できた」を待ってから次へ
⑥ 後片付け：snapshot/・out/・.lme2harness/mcp-token.json を消してよいか、一覧を見せて私の「OK」を待ってから消す

【私とのやり取りのルール】
- 私に頼むのは、私にしかできないことだけ（ブラウザでのログイン、キーを貼る、エルメや LINE の画面の操作、OK の返事）。1回に1つ、短い日本語で、どこを押すかまで書く
- API キーやシークレットは、絶対にチャットに書かせない。必要になったら keys コマンドを実行する。テキストエディットで .env が開くので、私は = の右に貼って ⌘S で保存するだけ。keys は保存されるまで最大10分待つ
- login・keys（私の操作を待つ）と migrate（時間がかかる）は、途中で止まらないよう、待ち時間を長くするか裏で動かして実行する
- 書き込み・デプロイ・削除の前は、何をするか一言伝える。エラーが出たら自分で調べて直し、私には結果と、次に私がやることだけを伝える
- 自分で調べて直しても同じところで2回続けて進めないとき、または私が「問い合わせたい」と言ったときは、作業を止めて、①今の段階 ②実行したコマンド ③エラー文 ④試したこと を、APIキー・シークレット・顧客の名前を消して10行以内の「問い合わせ用まとめ」にして見せる。そのうえで「作者のLINE（https://line.miyabiai.jp/r/oss-ai-261024）にこのまとめを送れば相談できます」と案内する。LINEへ送るのは私（あなたは送らない）
- 話すたびに、今どこかを ①準備 ②ログイン ③移行 ④並行運用 ⑤切り替え ⑥後片付け で示す
```

## 困ったとき

チャットにそのまま書いて大丈夫です。

```text
今どこまで進んだか、次に私がやることを1つだけ教えてください。
```

チャットを閉じてしまったときは、新しいチャットに上のメッセージをもう一度貼ってください。作業フォルダの状態を見て、続きから進めます。

AI が同じところで進めなくなったときは、AI が「問い合わせ用まとめ」を作って、作者（みやび｜Lゼロ）の LINE を案内します。まとめをそのまま LINE に貼って送ってください（無料・個人で返しているため、お返事まで時間がかかることがあります）。自分から相談したいときは、チャットに次のように書いてください。

```text
問い合わせたいので、問い合わせ用まとめを作ってください。
```

API キー・`.env` の中身・顧客の名前が写った画面は、LINE にも送らないでください。
