# エルメ → L Harness 移行 手順書（詳細版）

README の 5 ステップを、画面のどこを見るかまで含めて書いたものです。

## 0. 準備（init / login / doctor）

ふだんは README の 3 コマンド（`init` → `login` → `migrate`）で足ります。この手順書は、各段を個別に動かしたいときや、うまくいかないときのためのものです。

| もの | どこで取る | 入れる先 |
|---|---|---|
| L Harness の Worker URL・D1 の名前と ID | `init` が L Harness の導入フォルダ（`~/.line-harness` など）から自動で読む | `lme2harness.config.json` |
| L Harness の API キー | create-line-harness の完了画面の「API Key」 | `init` で貼る（`.env` の `HARNESS_API_KEY`） |
| エルメへのログイン | `npx lme2harness login`（ブラウザが開く） | 自動保存（`.lme2harness/mcp-token.json`）。移行元のアカウントも自動で設定 |
| エルメ 公開 API キー（任意） | エルメ管理画面 → 設定 → API 設定 → 発行 | `.env` の `LME_API_KEY`。ブリッジでタグ名を引くのに使う |
| エルメ Webhook 転送の署名シークレット | エルメ管理画面 → Webhook転送 | `.env` の `LME_WEBHOOK_SECRET`（ブリッジを使うとき） |

L Harness を別の場所に入れた場合は `npx lme2harness init --harness-dir <フォルダ>`。準備ができたかは `npx lme2harness doctor` で確かめられます（何も書き換えません）。

wrangler は L Harness のセットアップ時にログイン済みのはずです。別のアカウントで動かす場合は `.env` の `CLOUDFLARE_API_TOKEN` / `CLOUDFLARE_ACCOUNT_ID` に入れると、そちらが優先されます。

## 1. extract（取り出し）

```bash
npx lme2harness extract
```

- マスタ（タグ・項目・ステータス・ステップ配信・テンプレ・フォーム・自動応答・あいさつ・リッチメニュー・流入経路・予約・商品）→ `snapshot/*.json`
- 友だち 1 人 = `snapshot/friends/<エルメID>.json`（詳細＋会話履歴）
- 途中で止めたら、同じコマンドで続きから再開します。全部取り直すときは `--no-resume`
- 友だち 1 万人で、MCP ありなら 30 分前後、API だけなら 1〜2 時間が目安（読み取り制限 300 回/分）

## 2. plan（変換）

```bash
npx lme2harness plan
```

- `out/report.md` … 対応表と注意点。**必ず読む**
- `out/sql/NN_テーブル_001.sql` … 流す順に番号付き
- `out/plan.json` … apply が読む一覧
- `out/rich_menus.json` / `out/bookings.json` … 手動対応用の書き出し

本番に流す前に制約だけ確認したいときは、L Harness の `packages/db/bootstrap.sql` を指定します。

```bash
npx lme2harness plan --local-schema /path/to/line-harness-oss/packages/db/bootstrap.sql
```

## 3. apply（投入）

```bash
npx lme2harness apply            # 本番 D1（--remote）
npx lme2harness apply --dry-run  # 対象ファイルだけ表示
npx lme2harness apply --local    # wrangler dev 用のローカル D1
```

- 流したファイルは `out/apply-state.json` に記録され、再実行時は飛ばします。途中から流し直すときは `--from <番号>`
- 1 ファイル 400 文・約 900KB 以下に分けています（D1 の 1 回あたり上限に収まる大きさ）

## 4. verify（確認）

```bash
npx lme2harness verify
```

D1 の件数と計画の件数を突き合わせ、先頭 3 人を L Harness API で読めるか確認します。

## 5. enrich（アイコン取得・任意）

```bash
npx lme2harness enrich
```

L Harness 標準のプロフィール再取得 API を20人ずつ呼び、表示名・アイコン・ステータスメッセージを更新します。無料プランの Worker は1回の処理で外部通信50件までのため、20人ずつにしています。ブロック中の人は対象外です。

## 6. richmenu（リッチメニューの取り込み）

```bash
npx lme2harness richmenu --dry-run   # 対応だけ表示
npx lme2harness richmenu             # 取り込む
```

エルメが LINE に登録したリッチメニューを、L Harness の管理画面で扱えるように取り込みます。LINE 上の表示・人ごとの表示は変わりません。エルメのメニューとは名前・大きさ・ボタン数で突き合わせ、決めきれないものは取り込みません。タブ切替を含むメニューは L Harness が取り込みに対応していないため、管理画面で作り直してください。

並行運用中は、取り込んだメニューで「公開」「公開停止」を押さないでください。LINE 上のメニューが作り直され、エルメが人ごとに出しているメニューが外れます。

## よくある質問

**Q. 既に L Harness で友だち登録が始まっているけど大丈夫？**
A. 大丈夫です。同じ LINE ID の友だちは表示名・アイコンを上書きせず、エルメ由来のメタデータとタグだけ足します。

**Q. タグの名前がかぶったら？**
A. 既存タグを再利用します（`reuse_existing_tags`）。エルメ内で同名が複数あれば「名前 (2)」になります。

**Q. 移行後、ステップ配信が勝手に動かない？**
A. 動きません。シナリオ・自動返信・フォームはすべて停止状態で作ります。切り替え後に管理画面で有効化してください。

**Q. L Harness の管理画面のアドレスを開くと「Nothing is here yet」と出る**
A. create-line-harness がリリース版（タグ）を取り出した状態で管理画面を公開すると、「お試し版」としてだけ公開され、本番のアドレスには何も載らないことがあります。L Harness の `apps/web` で `NEXT_PUBLIC_API_URL=<Worker の URL> pnpm run build` してから、`wrangler pages deploy out --project-name <管理画面のプロジェクト名> --branch main` で公開し直してください。

**Q. エルメのテンプレートにあった計測リンク（[CONVERSION_…]）は？**
A. エルメ独自の仕組みなので移りません。`out/report.md` の「不明な差し込みタグ」に出るので、行き先の URL に置き換えてください。

**Q. 「どのステップまで送ったか」は移せる？**
A. ほとんどの場合は移せます。エルメ自体は進み具合を出しませんが、会話履歴に「ステップ配信で送ったメッセージ」が残っているので、ステップの本文と順番どおりに照合して「何通目まで届いたか」を復元し、続きの予定時刻を入れます。エルメの会話履歴は半年ほどで消えるため、それより前に始まって今も配信中の人だけは位置が分からず「一時停止」で入ります（人数は `out/report.md` に出ます）。L Harness の画面からは一時停止を再開できないので、続きが必要な人は手動で送るかシナリオに入れ直してください。
